# 统一响应与业务错误码

本文记录 `gateway-api` 当前实际响应契约。实现以
`services/gateway-api/internal/response/response.go` 为准。

## 响应结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

- HTTP 状态码表达传输层结果，`code` 表达前端可判断的业务结果。
- 成功时 HTTP 状态和业务码均为 `200`，不存在 `success` 字段。
- 失败码通常为五位：前三位对应 HTTP 状态，后两位区分业务场景。
- `data` 的具体结构由接口决定；失败时通常为 `null`。
- 前端可以展示 `message`，但不应依赖中文文案判断业务分支。

## 当前网关错误码

| HTTP | 业务码 | 默认含义 |
|---:|---:|---|
| 400 | 40001 | 请求参数错误 |
| 400 | 40002 | 验证码错误或已失效 |
| 400 | 40003 | 用户名或密码错误 |
| 400 | 40005 | 密码强度不符合要求 |
| 400 | 40006 | 旧密码错误 |
| 401 | 40101 | 未提供登录凭证 |
| 401 | 40102 | Token 非法、过期或已失效 |
| 403 | 40301 | 账号已禁用 |
| 403 | 40302 | 无权限访问 |
| 404 | 40401 | 账号或邮箱不存在 |
| 404 | 40402 | 资源不存在 |
| 409 | 40901 | 邮箱或资源冲突 |
| 409 | 40902 | 当前状态不允许该操作 |
| 429 | 42901 | 操作过于频繁 |
| 500 | 50001 | 未分类的服务内部错误 |
| 500 | 50002 | 邮件服务异常 |
| 500 | 50003 | OSS 上传异常 |
| 502 | 50005 | 下游 RPC 或 Java 服务不可用 |

部分 Java 代理接口仍由 `platform-java` 的 `Result<T>` 和异常处理器生成响应。
新增接口时应保持相同 Envelope，并逐步收敛到上表，避免 Go/Java 同一错误使用不同业务码。

## gRPC 到 HTTP 的映射

网关会将常见 gRPC 状态转换为 HTTP 与业务码：

| gRPC 状态 | HTTP | 业务码 |
|---|---:|---:|
| `InvalidArgument` | 400 | 40001 |
| `NotFound` | 404 | 40401 或 40402 |
| `AlreadyExists` | 409 | 40901 |
| `FailedPrecondition` | 409 | 40902 |
| `PermissionDenied` | 403 | 40301 或 40302 |
| `Unauthenticated` | 401 | 40102 |
| `ResourceExhausted` | 429 | 42901 |
| `Internal` | 500 | 50001 或 50002 |
| `Unavailable` | 502 | 50005 |

修改映射时必须同步更新网关单元测试、前端错误处理和本文。
